Test automation framework for the [**Tutti Frutti**](https://github.com/Valerii-Synenko/tutti-frutti) fruit
marketplace, covering the API/gRPC, the web UI and the database layer in one pytest project.

## Application under test

[Tutti Frutti](https://github.com/Valerii-Synenko/tutti-frutti) is a lightweight microservices demo shop that sells
fruit, built as a playground for backend/API and UI test automation (a
[Sock Shop](https://github.com/microservices-demo/microservices-demo) alternative). It includes:

- a **gateway** (FastAPI BFF) as the single entry point for the UI
- **users**, **catalogue** and **orders** services (FastAPI + PostgreSQL / MongoDB)
- an **inventory** service in Go, reachable only over gRPC
- an **AI fruit assistant** built on the Anthropic API
- a **React** UI where every interactive element has a `data-testid`

Users can become sellers and list fruit, admins moderate listings, and checkout runs a simulated card payment,
which gives plenty of business logic to test.

## Features

- **REST API tests** on top of Playwright's `APIRequestContext`, with typed clients grouped in an `ApiHub`
- **UI tests** with Playwright using the Page Object pattern (pages + reusable components)
- **Database checks** against PostgreSQL (`psycopg` + connection pool), with clients grouped in a `DbHub`
- **Typed request/response models** with Pydantic v2, and test data generated by
  [polyfactory](https://github.com/litestar-org/polyfactory) and [Faker](https://faker.readthedocs.io/)
- **Self-cleaning fixtures**: users created during a test are deleted from the database afterwards
- **Qase TestOps reporting** with suites, steps, severities and test case IDs
- **Configuration via `.env`** loaded by `pydantic-settings`
- Planned: gRPC tests, Locust load tests and LLM evaluations with DeepEval

## Getting started

### Prerequisites

- Python 3.14
- [uv](https://docs.astral.sh/uv/getting-started/installation/)
- A running instance of [Tutti Frutti](https://github.com/Valerii-Synenko/tutti-frutti#quick-start)
  (`make up && make seed`)
- A [Qase](https://qase.io/) project and API token (optional, to publish test runs)

### Installation

```bash
git clone https://github.com/Valerii-Synenko/tutti-frutti-py-tests.git
cd tutti-frutti-py-tests

uv sync --all-extras
uv run playwright install chromium
uvx pre-commit install
```

### Configuration

Copy the example file and fill in the values:

```bash
cp .env.example .env
```

| Variable                    | Description                                |
|-----------------------------|--------------------------------------------|
| `BASE_API_URL`              | Base URL of the REST API                   |
| `BASE_UI_URL`               | Base URL of the web application            |
| `ADMIN_EMAIL`               | Admin account email                        |
| `ADMIN_PASSWORD`            | Admin account password                     |
| `ADMIN_NAME`                | Admin account display name                 |
| `USER_DB_URL`               | PostgreSQL connection string               |
| `QASE_TESTOPS_API_TOKEN`    | Qase API token                             |
| `QASE_TESTOPS_PROJECT`      | Qase project code (e.g. `TF`)              |
| `QASE_MODE`                 | `off` (default) or `testops`               |
| `QASE_TESTOPS_RUN_COMPLETE` | Complete the run in Qase after the session |

## Running tests

```bash
# All tests
uv run pytest

# By marker
uv run pytest -m api
uv run pytest -m ui
uv run pytest -m db

# UI tests in a visible browser
uv run pytest -m ui --headed
```

Available markers: `api`, `ui`, `db`, `grpc`, `ai`.

## Reporting

Results are published to [Qase TestOps](https://qase.io/) by the `qase-pytest` plugin. The plugin reads its settings
from environment variables, so load `.env` with `--env-file` and enable the `testops` mode for the run:

```bash
QASE_MODE=testops uv run --env-file .env pytest
```

With `QASE_MODE=off` (the default) nothing is sent to Qase. Tests are linked to Qase test cases via `@qase.id(...)`.

## Code quality

```bash
uv run ruff check --fix .   # lint
uv run ruff format .        # format
uv run ty check             # type check
```

Ruff runs automatically on every commit via pre-commit.
